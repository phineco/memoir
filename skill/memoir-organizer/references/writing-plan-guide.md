# 写作计划指南（writing-plan-guide）

管理员在网站「📋 写作计划」页定好"先写谁"（可让 AI 先给建议再手动改），
skill 每次会话开始时拉取当前计划，按计划引导用户补故事、跟进未完成项。

## 一、获取计划

接口：`GET /api/writing-plan?family_id=<家庭 id>`（家庭 id 是网站自动生成的标识，
在家庭页地址 `/f/<家庭 id>` 里，**没有"家庭代号"这种东西，不要向用户索要代号**）。

**该接口需要登录且必须是该家庭成员，skill 在外部环境没有网站会话，不能直连拉取。**
获取计划的唯一主路径：请管理员在登录状态下，把计划内容粘贴到对话里
（标题 + 人名 + 状态即可）；管理员若能打开上面接口，把返回的 JSON 整段粘贴回来更好。

返回结构（供管理员粘贴 JSON 时对照）：
```json
{"family_id": "2daab4ad", "plan": {
  "id": "xxx", "title": "王家·冬季采访计划",
  "items": [{"person_id": "网站侧人物id", "person_name": "王德顺", "order": 1,
             "status": "pending|doing|done", "note": "备注"}]}}
```

- `plan` 为 null 表示没有当前计划 → 走正常流程（家族树前置模式给采访顺序建议）。
- 返回 items 里的 `person_id` 是**网站侧**人物 id，与 skill 侧 id（如 p01）不是一套，
  匹配人物一律以 `person_name` 为准。

## 二、匹配到当前用户

1. 先做讲述者确认（organizing-guide §一.0）：问清"这次是谁讲的"，对应到树上人物。
2. 在计划里找这个人：
   - 找到 → 本次优先处理他的条目：status=doing 接着上次继续；pending 则开始他的第一个故事。
   - 没找到（计划里没有他）→ 告诉用户"计划里这次没排到你，先按计划走 XX（第一位 pending/doing 的人），还是你想先讲自己的？"，由用户定。
3. 认领了树上人物的登录用户在网站计划页会看到"👤 你"标记，skill 侧同样口头点出来。

## 三、引导话术

- **补齐故事**（pending）："计划里下一位是三叔（王建军），备注说'供销社经历待深挖'。这次我们讲三叔的故事好吗？先从他进供销社那年讲起？"
- **继续未完成**（doing）："上次三叔讲到 1985 年电视机专柜，咱们接着往下讲？"
- **已完成**（done）跳过，除非用户主动想补充。
- 一次只推一个人，不要一次列全计划。

## 四、进度回写

采访/整理产出后，按 sync-guide 生成 `plan_progress` 数据包回写网站：

```sync-json
{"type": "plan_progress", "clientId": "<新uuid>",
 "payload": {"plan_id": "<计划id，可空=当前计划>",
   "items": [{"person_name": "王建军", "status": "doing"},
             {"person_name": "王德顺", "status": "done"}]}}
```

- 人物匹配：**优先用 person_name**（最稳）；skill 侧 person_id（如 p01）也可带，
  网站走映射表解析，对不上会被忽略。
- status 只能是 pending / doing / done。
- 触发时机：某人物的故事线本次有进展（开始做 → doing；初稿完成/已核实 → done）时，
  随本次的同步节点一起输出（见 SKILL.md 规则 9）。

## 五、诚实边界

- 计划是"建议顺序"，用户随时可以插队、跳过——计划服务用户，不绑架用户。
- 网站计划改了（管理员调整），以最新拉取的为准；冲突时先问用户。
- 没有计划、拉不到计划时，不编造计划，直接走正常采访流程。
