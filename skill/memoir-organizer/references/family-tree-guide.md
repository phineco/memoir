# 家族树梳理规则（memoir-organizer）

本文件规范"前置：家族树"模式。目标：正式采访前，用追问建立完整人物地图，之后按人物逐个完善故事线。

## 一、追问式建树流程

1. **起点**：先确认起点人物——"咱们先从谁开始理？一般从你本人或你父母开始。"默认从用户本人起。
2. **逐层扩展**（每层问完再往下一层，不要一次全问）：
   - 父母：父亲全名？母亲全名？是否健在？
   - 祖父母：爷爷奶奶、姥爷姥姥的全名？（如已故，问大致生卒年份）
   - 兄弟姐妹：几个？排行？每人姓名？
   - 配偶、子女：姓名？
3. **每人四问**（提到一个人就地追问，不攒到最后）：
   - 全名是什么？（称谓如"三叔"不够，必须要全名；实在不知道标 `[待核实]`）
   - 和起点人物的关系？
   - 是否健在？（如已故：大致哪年去世？）
   - 备注：现居地 / 关键身份（如"县城供销社上班"），一句话即可。
4. **冲突处理**：用户前后说法不一致（如先说"三叔叫王建国"，后说"叫王建军"），立即指出并请确认，不要自行取舍。

## 二、输出：文字版家族树

用辈分缩进呈现，示例：

```
王德顺（爷爷，1905–1978）✔️已核实
├─ 王建国（父亲，1938–，健在）📝整理中
│   ├─ 王秀兰（本人，1965–，健在）⏳待采访
│   ├─ 王建军（三叔，1945–，健在）⏳待采访
│   └─ 王秀英（姑姑，1950–2019）⏳待采访
└─ …
```

下方附人物清单表：姓名 | 关系 | 生卒 | 状态 | 备注（故事线索，如"供销社上班/当过兵"——这些是后续采访的切入点）。

## 三、故事线规划

1. **AI 给顺序建议**，默认规则：
   - 健在的长辈优先（抢救性记录），辈分从高到低；
   - 同辈中按"故事线索多"优先（如当过兵、经历过大事的人）；
   - 明确说"这只是建议，你可以调整"。
2. **用户选定一人** → 进入该人物的采访模式（SKILL.md 步骤 2）或整理模式（步骤 1），产出该人物的初稿包。
3. **完成后**：更新该人物状态（⏳→📝→✅→✔️），主动推荐下一位："王建国（父亲）的初稿完成了，下一个建议采访三叔王建军，他在供销社那段可能有很多故事。继续吗？"
4. **跨人物串联**：整理某人故事时提到另一人物，自动在那个人物备注里加一条线索（如"王秀兰提到三叔带糖块"），采访到那个人时提醒。

## 四、与整理模式的衔接

- 家族树里的人物全名，自动成为整理模式待核实清单的"已知答案"——初稿里再出现"三叔"，不再列为待核实，直接用全名。
- 用户在任何时候说"回到家族树/看一下进度"，输出当前最新版树 + 各状态统计（如"共 9 人，已完成 2 人"）。

## 五、故事人物对应（实体对齐）

整理或采访中，每出现一个人名/称谓，必须做一次对应判定：

1. **能对上树**：称谓或名字与树上某人唯一匹配（如"三叔"对应树上唯一的王建军）→ 自动关联，后续统一用全名，不再追问。
2. **模糊**：称谓可能指向多人（如语境不明的"爷爷"）→ 追问一次确认："你说的'爷爷'是王德顺吗？"
3. **对不上树 = 新出现人物**：标记为 🆕，并追问两个问题 —
   - "这位是谁？和家里什么关系？"（一句话即可）
   - "要把他/她加入家族树吗？"（加入 → 按"每人四问"补信息；不加入 → 只在故事备注里保留，不入树）
4. **同名冲突**：故事里出现两个"建国" → 立即追问区分，并在树上用备注标注（如"王建国（大伯家）/ 王建国（同学）"）。
5. **事件对应**：故事里的关键事件（如"当兵""搬家""供销社上班"）自动记到对应人物的备注里，作为该人物采访时的切入点。
